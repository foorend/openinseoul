# OPEN IN SEOUL : CAFE — 첫 1년

서울의 다섯 상권(실제 행정동 공공데이터 기반)에서 카페를 열고, 현금·손익·사장 노동을 비교하는 브라우저 경영 게임입니다. 설치·로그인·빌드 과정이 없습니다.

공개 주소: https://openinseoul.foodtrend.news/ · 강사용 도구: https://openinseoul.foodtrend.news/education.html

## 실행·검사

```sh
npm run dev
# http://127.0.0.1:4173
npm run check
npm test
```

Node.js와 Python 3만 필요합니다. 개발 서버는 ES 모듈 캐시를 막습니다. 정적 HTTPS 호스팅으로 배포하며, 모든 게임 모듈·CSS에 같은 릴리스 태그를 사용합니다. 다음 릴리스에서는 전체 import graph와 HTML 진입점을 함께 갱신하세요.

## 플레이

- 간편 개업: 자본·내 시간 → 상권 → 카페 유형. 원두·집기·메뉴까지 설계하는 고급 모드도 남겨 두었습니다.
- 기본 3챕터: 1월 개업 → 4월 성장 → 9월 생존 → 12월 결산. 중간 달은 같은 계획·기본 이벤트 선택으로 자동 정산되며 기록에 표시합니다. 매달 직접 결정하는 12개월 모드도 있습니다.
- 영업 화면은 매장 장면 + 오른쪽 '오늘 장부' + 조작 한 줄입니다. 장부는 문 열 때 나간 월세·인건비에서 시작해 판매·재료·부가세 적립이 쌓이는 대로 이익, 고정비 회수율, 오늘 내 시급(이익 ÷ 사장 노동시간)을 실시간으로 보여 줍니다. 장면 위로는 판매(+₩)·문 열 때 나간 고정비·놓친 손님(−1)·돌발 선택의 비용이 뜹니다. 미니게임은 없습니다.
- 조작: 속도(Ⅱ·1×·4×·8×) · 사장 자리(키친·홀·입구 = 1·2·3) · 쉬기/복귀(스페이스) · 자동 배치(0). 8× 빨리 감기는 그날 결정을 하나 내린 뒤 열립니다. 손님·행인·테이블을 누르면 속마음 보기·전단지·응대·치우기를 합니다. 키친에 선 사장은 머신 청소와 쇼케이스 보충을 알아서 합니다.
- 마감은 영업이익, 투자로 나간 현금, 사장 노동을 분리합니다. 연말의 세후 현금·순이익·사장 시간당 수익을 함께 확인합니다.
- 첫 영업일에는 시계를 멈추고 실제 화면의 세 곳(오늘 장부 → 사장 자리 → 손님)을 말풍선으로 짚어 줍니다. 건너뛸 수 있습니다.
- 작은 화면에서는 장면 → 장부(3×2) → 조작부 순으로 한 화면에 쌓입니다. 23:00이 되면 마감 영수증으로 넘어갑니다. 마감 영수증은 영업 중 장부와 같은 다섯 줄(매출·인건비·월세·재료·수수료·기타)과 시급, 놓친 손님 상위 2개를 먼저 보여 주고 퍼널·리뷰·장사 노트·조건 비교는 '자세히'에 둡니다. 월 마감도 다섯 줄 영수증과 월 시급, '하루 감각 vs 한 달 현실'을 먼저 보여 주고 14줄 원장은 펼쳐 읽습니다.
- 관측한 이탈을 바탕으로 비교 가설 하나를 먼저 제안합니다. 이익 변화 예상 → 같은 seed·버전·시작 상태에서 한 조건 비교 → 결과 해석 → 내 판단 기준 → 다음 달 적용 또는 유지까지 해야 결정 미션을 완료합니다. 추가 노동 1시간당 증가 이익 또는 확보한 시간의 비용을 함께 설명합니다. 실제 응답은 브라우저 게임 저장에 남으며 교육 효과를 증명하는 점수가 아닙니다.
- 영업시간·직원 편성·사장 근무 외에 메뉴 한 개 교체도 비교합니다. 설비·업태·납품 종류 제한을 검사하며, 원래 게임은 비교만으로 변하지 않습니다. 나쁜 결과도 그대로 표시하고 유지 선택을 허용합니다.
- 직원이 없는 가게에는 인력 감축을 제안하지 않습니다. 구 저장의 잘못된 감축 편성도 직원 없이 사장 추가 근무를 만들지 않습니다.
- 월 마감 후 ‘내 조건으로 계산’에서 준비 총자금·초기 총투입금·월세·생활비를 입력하고 가정과 결과를 텍스트로 저장합니다. 월세만 바꾸는 장부 민감도 계산이며 실제 수요 예측·게임 조건 적용은 아닙니다. 연말 세금·대출 원금 상환·추가 투자와 계절 변화는 소진기간에 반영하지 않습니다.
- 5초마다·화면 전환·탭 종료 시 저장하고 수동 저장도 제공합니다. 이어하기는 일시정지 상태로 복원됩니다. 구버전 기록은 JSON으로 보관할 수 있고 자동 삭제하지 않습니다.
- 도움말·출처·수업 안내를 읽는 동안 영업 시계와 영업 단축키는 멈춥니다.

## 데이터·해석 범위

버전 `seoul-cafe-2026.10-v3` · 확인일 2026-10-06. 화면의 ‘공식 기준·출처’에 기관 원문, 기준 시기, 단위, 변환 규칙과 게임 가정을 표시합니다.

상권의 임대료·경쟁도·수요 수준은 서울시 상권분석서비스 지역분석(2026년 2분기, 커피-음료) 행정동 공개 데이터에서 옵니다 — 강남=역삼1동, 을지로=을지로동, 성수=성수2가1·3동, 신촌=신촌동, 강동=명일1동. 월세는 3.3㎡당 월환산임대료×12평, 경쟁도는 점포 수, 수요 계수는 기준 매장의 연평균 월매출이 동네 점포당 평균 월매출과 같아지도록 보정합니다. 2026 최저임금 10,320원과 국세청 공개 기본세율을 계산에 쓰며, 매출 부가세는 포함 수입÷11 적립입니다. 시간대 분포·손님 구성·평일/주말 비중·권리금·메뉴 원가·수수료·보험·대출은 게임 가정입니다. 화면 아래 출처 바가 지금 보이는 숫자의 출처를 계속 보여 줍니다.

공공데이터 갱신(분기마다): `python3 tools/fetch_public_data.py 2026 3` → `node tools/calibrate.mjs` 출력의 DEMAND_INDEX를 `src/data.js`에 반영 → `npm test`.

평일·주말 대표일로 월을 추정합니다. 주휴·가산수당, 감가상각, 실제 세액 공제, 보증금 회수, 대출 원금 상환·폐업 청산은 미반영입니다. 실제 창업·세무·투자 판단이나 법인 전환 추천에 사용하지 마세요.

코치는 기본적으로 결정적 계산 결과와 고정 설명을 사용합니다. **생성 AI 서버는 연결하지 않았습니다.** 선택적인 동일 출처 `/api/...` 연결 계약은 `src/coach.js`에 있으며, 미연결·시간초과·응답 검증 실패 시 계산 설명으로 돌아갑니다. 브라우저에 API 키를 넣지 마세요. 실제 AI 연결에는 서버 구현·인증 정보·정성 설명 검수가 별도로 필요합니다. Hive도 현재 로컬 대체 구현이며 실제 운영 연동을 검증한 것이 아닙니다.

## 익명 수업·파일럿

1. 강사가 `education.html`에서 수업 코드·주제를 정해 링크를 만듭니다. 학생은 로컬 저장·직접 파일 전달 안내에 동의합니다. 공통 시작 자본은 1억 5천만원이며 같은 코드의 난수를 사용합니다. 상권·업태·대출·운영 선택은 달라질 수 있습니다.
2. 학생이 플레이 전 객관식 3문항과 자신감 1–5에 응답합니다. 시작 직후 ‘교육 결과 저장’에서 JSON을 강사에게 전달하세요. 이 파일이 없으면 미완주자를 포함한 모집단을 알 수 없습니다.
3. 완주 후 사후 응답과 최신 JSON을 전달합니다. JSON의 `decisions`에는 직접 영업한 날마다 내린 결정(시각+내용)과 그날 이익·사장 노동시간이 남습니다. 재도전은 같은 익명 참가자 ID와 새로운 runId를 사용합니다. 최신 100시도는 이 브라우저에 보관합니다.
4. 강사는 JSON 파일 여러 개·붙여넣기로 결과를 모읍니다. 같은 runId는 최신 기록만 반영합니다. 수업별 완주·재도전·출처 열람·조건 비교·사전후 이해도·별도 자신감·시간당 수익을 CSV로 내보냅니다. 돈 단위는 만원, 시급은 원/시간입니다.

이름·이메일·연락처·가게 이름은 교육 결과에 포함하지 않습니다. 교육 파일은 자동 서버 전송하지 않으며 강사 화면은 탭 메모리에서만 읽습니다. 새로고침 전에 CSV를 저장하세요. 로컬 기록 삭제는 해당 사이트의 브라우저 저장 데이터 삭제로 가능합니다(게임 진행도 함께 지워집니다).

완주율·재도전율은 가져온 고유 참가자 기준입니다. 사전/사후 쌍이 없는 결과는 개선 평균에서 제외합니다. 반복 문항·자기보고 파일·자유 선택 조건이므로 교육의 인과효과를 입증하지 않습니다. 신청서의 30명 파일럿, 완주 70%·재도전 40%는 모집 후 측정할 목표이며 개발 테스트의 성과로 주장하지 않습니다.
